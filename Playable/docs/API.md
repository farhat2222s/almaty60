# ALMATY 60 — локальный игровой сервер

Это самостоятельная демонстрационная веб-игра на Node.js без внешних серверных зависимостей. Сервер ведёт одного локального игрока. APORTA, STEPPE, ALMA, NOMAD и SARY — демонстрационные кампании: коды не дают права на реальные товары, скидки или посещения. Виртуальное перемещение не подтверждает физическое присутствие в Алматы.

## Запуск и проверки

В папке `Playable`:

```sh
node server.mjs
```

Открыть `http://127.0.0.1:3060`. Требуется Node.js 22+; фактические автоматические проверки выполнены Node.js 24. По умолчанию сервер слушает **только 127.0.0.1**. Номер порта можно задать переменной `PORT`. Для проверки логики сеть и открытый порт не нужны:

```sh
node --test tests/server.test.mjs
```

Прогресс автоматически сохраняется в `data/game-state.json`. Первичная установка создаёт нового игрока с нулевым балансом. Перед новым прохождением сохраните копию этой папки. Исходные материалы из Downloads этот сервер не использует и не изменяет.

## Общие правила

- Мутации принимают JSON-объект с `Content-Type: application/json`; максимальный размер — 16 КБ.
- При наличии `Origin` он должен точно совпасть с локальным адресом страницы, включая порт. Сторонние Host и cross-site запросы отклоняются. Это защита границы локальной демонстрации, **не аутентификация**.
- Успех: HTTP 200 и JSON. Ошибка: HTTP 400/403/404/409/413/415/429 с `{error,message,demo:true}`.
- Все игровые мутации возвращают полный снимок состояния, кроме явно отмеченных ниже.
- Сервер хранит прогресс, позиции и результаты. Клиент не передаёт итоговый результат, XP, баланс, произвольную позицию или время попытки.
- Таймер попытки основан на монотонных часах процесса. `serverNow`, даты результатов и сроков привязаны к ним; изменение клиентских часов не влияет на попытку. При перезапуске сервера незаконченная попытка завершается поражением без награды.
- Состояние сохраняется заменой временного файла в том же каталоге. Погашение кода и запись статуса выполняются синхронно, до ответа. Движение сохраняется раз в 30 входящих кадров; важные действия — сразу. Аварийное завершение может потерять несколько последних шагов.

## Состояние мира

`GET /api/state`

```js
{
  player: {
    id: 'local-player', name: 'Исследователь', xp: 0, coins: 0, level: 1,
    position: {x: 0, z: 18}, skin: 'night', vehicle: false,
    inventory: ['night'], discovered: [], collected: [], quests: [],
    achievements: [], stats: {wins: 0, attempts: 0, distance: 0}
  },
  missions: [], brands: [], landmarks: [], npcs: [], campaigns: [],
  rewards: [], history: [], activeAttempt: null, lastAttempt: null,
  serverNow: 0, demo: true
}
```

В исходном наборе: 20 миссий, 5 демо-брендов, 6 достопримечательностей, 3 квестовых NPC и 18 городских яблок. Полное описание геометрии находится в `public/world-data.mjs`. История API содержит последние 200 записей; сохранение хранит весь журнал. Повторное посещение не выдаёт повторную награду за ту же достопримечательность или яблоко.

Уровень равен `1 + floor(xp / 300)`. Достижения — объекты `{id,title,earnedAt}`, коллекции `discovered`/`collected` — массивы ID. Квесты содержат `{id,title,description,status,progress,total,xp,coins,acceptedAt,completedAt?}`; статусы `active` и `completed`.

## Свободная игра

| Маршрут | JSON | Поведение |
|---|---|---|
| `POST /api/input` | `{x,z,sprint?}` | `x` и `z` — направления от −1 до 1. Сервер нормализует диагональ и рассчитывает смещение. |
| `POST /api/npc` | `{id}` | В радиусе 12 принять поручение или получить его награду после выполнения. Повторная выдача запрещена. |
| `POST /api/vehicle` | `{buy?:true}` | Купить самокат за 120 Coins при необходимости и переключить езду/ходьбу. Повторное переключение бесплатно. |
| `POST /api/player` | `{name?,skin?}` | Имя до 30 символов. Стиль `night` бесплатный, `cyan` — 80, `gold` — 150 Coins; повторный выбор купленного стиля бесплатный. |

Скорости: ходьба 14, бег 22, самокат 36 игровых единиц в секунду. Интервал одного ввода ограничен 0,25 секунды. Дробные шаги и проверка геометрии препятствуют проходу сквозь здания. Клиент должен присылать направления примерно 15–30 раз в секунду. Дополнительные поля `position`, `elapsed`, `xp` не используются для управления состоянием.

Открытие достопримечательности в радиусе 10: +60 XP и +20 Coins один раз. Яблоко в радиусе 3: +15 XP и +5 Coins один раз.

| NPC | Поручение | Награда |
|---|---|---|
| `aida` | Открыть 3 достопримечательности | 200 XP, 100 Coins |
| `timur` | Собрать 8 яблок | 250 XP, 120 Coins |
| `dana` | Победить в 3 миссиях | 300 XP, 150 Coins |

Прогресс поручений учитывает уже выполненные действия; за наградой нужно вернуться к NPC.

## Миссии и попытки

`POST /api/missions/:id/start` с `{}` начинает попытку. Для `collect`, `checkpoint` и `delivery` игрок должен находиться не дальше 14 единиц от `mission.start`. `reaction` доступна из любой точки игрового мира. Одновременно разрешена одна попытка. Недоступная, ещё не начавшаяся или законченная кампания, исчерпанный лимит наград и повторный старт ранее 10 секунд после победы отклоняются.

```js
activeAttempt: {
  id, missionId, type, status: 'active', startedAt, expiresAt, duration,
  targets: [{x,z,done}], progress, total, remainingSeconds,
  errors, reaction: null
}
```

- `collect`: собрать все цели в любом порядке.
- `checkpoint`: пройти точки последовательно.
- `delivery`: забрать и доставить предмет через упорядоченные точки маршрута.
- Радиус цели — 4,5 единицы. Выполнение определяется сервером при обработке движения.
- `reaction`: 8 последовательных правильных ответов. `POST /api/attempt/action` с `{symbol:'↑'}`; остальные символы `→`, `↓`, `←`. Сервер выдаёт `{symbol,cue,readyAt,step,errors}`. Стрелку следует показывать после `readyAt`; ответ должен поступить не ранее чем через 250 мс после этого момента. Ранний или неправильный ответ сбрасывает серию и добавляет ошибку. Третья ошибка завершает попытку поражением.
- `POST /api/attempt/abandon` с `{}` — отказаться, награда не выдаётся.
- На нуле сервер завершает попытку поражением. Клиентский таймер служит отображением.

После завершения `activeAttempt` становится `null`, а `lastAttempt` содержит `status:'won'|'failed'`, `finishedAt`, `reason` и, при выдаче, `rewardId`. Успех выдаёт XP, Coins и уникальный демонстрационный код; отказ, таймаут и ошибки наград не дают. Если кампания была остановлена или закончилась во время попытки, игровая победа и XP/Coins сохраняются, но код не выдаётся. Повторная отправка результата невозможна: endpoint для клиентского утверждения победы отсутствует.

## Награды и сотрудник

```js
{
  id, code: 'DEMO-…', playerId, brandId, campaignId, missionId, title,
  status: 'AVAILABLE', createdAt, expiresAt, redeemedAt: null, demo: true
}
```

Срок кода — 7 суток. Модель статусов: `AVAILABLE`, `USED`, `EXPIRED`, `CANCELLED`; отмена зарезервирована в модели, отдельного endpoint отмены в этом срезе нет.

| Маршрут | JSON | Ответ |
|---|---|---|
| `POST /api/rewards/inspect` | `{code}` | `{reward,valid,demo:true}`; код или ID существующей награды. |
| `POST /api/rewards/redeem` | `{code}` | Полное состояние плюс `reward`, статус `USED`, время `redeemedAt`. |

Неизвестный код — 404. Повторный, истёкший или отменённый — 409. Проверка срока, смена статуса и сохранение выполняются сервером. Роль сотрудника в этой локальной демонстрации доступна пользователю того же компьютера без авторизации. Она предназначена для проверки цепочки и не должна использоваться с реальными призами.

## Демонстрационный кабинет бренда

`POST /api/campaigns`

```js
{
  brandId: 'aporta', title: 'Городской ритм', type: 'reaction',
  duration: 60, xp: 150, coins: 60, rewardLabel: 'Демо-подарок',
  maxRewards: 100, start: null, end: null
}
```

Тип — один из четырёх игровых типов. Продолжительность: 15/30/45/60/90/120 секунд. XP и Coins — целые 0–500, лимит наград — 1–10000, название до 80 символов, название награды до 120. `start`/`end` — ISO даты или `null`; сервер проверяет порядок и будущую дату окончания. Создаётся новая кампания с одной миссией на маршруте выбранного бренда. Ответ содержит `created:{campaign,mission}` и полное состояние.

`PATCH /api/campaigns/:id` с `{active:false}` останавливает кампанию, `{active:true}` возобновляет. Лимит применяется к общему числу выданных кодов кампании, включая уже использованные или истёкшие. Выдача не превышает лимит. Редактор произвольной геометрии маршрута, часы/дни недели и модерация не реализованы.

## Аналитика

`POST /api/events` с `{type:'open',missionId}` записывает фактическое открытие миссии. Остальные клиентские типы событий отклоняются; победы, старты и выдачи записывает игровая логика.

`GET /api/analytics` возвращает `opens`, `starts`, `completions`, `wins`, `rewards`, `redemptions`, `uniquePlayers`, `repeatVisits`, `startToWin`, `rewardToRedemption`, а также `byBrand`, `byCampaign`, `byMission` с теми же счётчиками. `completions` включает победы и поражения. `repeatVisits` здесь означает повторные старты одного локального игрока, а не подтверждённые визиты в заведение. Пустая история даёт нули; вымышленные пользователи и покупки не добавляются.

## Границы прототипа

Серверная проверка движения, времени, прогресса и одноразового погашения работает в локальной демонстрации. Однако владелец компьютера контролирует код и файл сохранения. Здесь нет аккаунтов, защищённых ролей бренда/сотрудника, PostgreSQL/Redis, серверной геопроверки, коммерческих интеграций, реальных промокодов, платежей, push, мультиплеера или полной системы антифрода. Существующие NPC не являются сетевыми игроками. Реальные призы требуют отдельного защищённого backend, авторизации, транзакционной базы и интеграции с партнёром. Этот веб-срез не является нативной Unreal-игрой для iOS/Android.

## Тестируемый модуль

`createGameService({dataDir:false,clock:{now,monotonic}})` создаёт сервис в памяти с подменяемыми часами. `game.handle(method,path,body)` исполняет те же операции, что HTTP; `game.flush()` сохраняет изменения. `createGameServer(options)` создаёт `http.Server` и открывает порт только после явного `listen`. Набор проверок охватывает четыре победные механики, поражения, порядок целей, таймаут и часы, ограничение движения, прогрессию и покупки, награды и повторы, лимиты кампаний, сохранение после рестарта, фактическую аналитику и HTTP-границу без открытого порта.
